3. Обработка ошибок

  "package_name": ""                   -> пустое имя
  "package_name": "bad name!"          -> недопустимый id
  "repository": "ftp://x"              -> нужен http(s) URL
  "test_mode": "да"                    -> нужен true или false
  "version": "1.x"                     -> некорректная версия
  "output_file": "graph.png"           -> нужно расширение .svg
  "output_file": "нет_папки/g.svg"     -> каталога не существует
  "max_depth": 0                       -> должно быть >= 1
  "max_depth": "3"                     -> нужно целое число
  уберёшь любую строку                 -> "отсутствуют параметры"
  лишний ключ "foo": 1                 -> "неизвестные параметры"
  test_mode true и несуществующий файл -> файл не найден
  test_mode true и имя "a"             -> имя из заглавных букв
  несуществующий конфиг:
    python -m depgraph --config configs\net_takogo.json
  битый JSON (убери запятую или скобку)

Ошибки репозитория (код завершения 1):
  Реальный режим, несуществующий пакет или версия:
    "package_name": "Net.Takogo.Paketa"  -> "не найдено: ..."
  Тестовый режим, "repository": "tests/data/broken.txt"
    -> "строка 2: нет символа ':'"
  Тестовый режим, "repository": "tests/data/undefined.txt"
    -> "пакет 'Z' не описан в репозитории"


4.Сравнение с dotnet
В отдельной папке (не в репозитории):

  dotnet new classlib -n cmp
  cd cmp
  dotnet add package Microsoft.Extensions.Logging --version 8.0.0
  dotnet list package --include-transitive
  dotnet restore -v d        # подробный порядок загрузки

Сравни список с графом из 1.1 и 1.4 (платформа net8.0 или netstandard2.0)
и впиши найденные расхождения в README (раздел "Сравнение с реальным
менеджером пакетов").

Типичные причины расхождений:
  - зависимости разные для разных платформ (framework);
  - NuGet берёт одну версию пакета, у меня вершина = (имя, версия);
  - dotnet грузит пакеты параллельно, порядок не фиксирован;
  - пакеты, входящие в платформу, dotnet не скачивает.
