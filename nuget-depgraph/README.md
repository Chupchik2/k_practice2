# depgraph — граф зависимостей пакетов NuGet

Инструмент командной строки для построения и визуализации графа зависимостей
пакетов .NET (NuGet). Python 3.10+, только стандартная библиотека; менеджеры
пакетов и сторонние библиотеки для получения зависимостей не используются.

## Возможности

- Параметры задаются JSON-файлом, все значения проверяются.
- Прямые зависимости заданной версии пакета читаются из `.nuspec`
  репозитория NuGet (flat container API) по HTTP.
- Граф строится обходом в ширину без рекурсии с ограничением глубины.
- Циклические зависимости обрабатываются и отображаются (пунктир).
- Порядок загрузки: зависимости раньше зависимых.
- Вывод: текст Mermaid (на экран и в `.mmd`) и изображение SVG.
- Тестовый режим: граф из текстового файла, пакеты — заглавные буквы.

## Конфигурация

Пример — `config.example.json`.

| Параметр       | Описание                                                  |
|----------------|-----------------------------------------------------------|
| `package_name` | Имя анализируемого пакета                                 |
| `repository`   | URL репозитория или путь к файлу тестового репозитория    |
| `test_mode`    | `true` — `repository` это файл; `false` — URL             |
| `version`      | Версия пакета (в тестовом режиме может быть пустой)       |
| `output_file`  | Имя SVG-файла; рядом сохраняется `.mmd` с тем же именем   |
| `max_depth`    | Максимальная глубина анализа, целое >= 1                  |
| `framework`    | Необязательно. Платформа, по умолчанию `.NETStandard2.0`  |

Ошибки конфигурации: код завершения 2; ошибки репозитория и записи: код 1.

## Запуск

```
make run CONFIG=config.example.json       # граф + Mermaid + SVG
make test                                 # тесты (unittest)
```

Без `make`: `PYTHONPATH=src python3 -m depgraph --config FILE [опции]`.

| Опция           | Действие                                              |
|-----------------|-------------------------------------------------------|
| `--show-config` | Этап 1: вывести параметры как ключ-значение           |
| `--direct-deps` | Этап 2: вывести прямые зависимости пакета             |
| `--load-order`  | Этап 4: вывести порядок загрузки зависимостей         |

Опции этапов 1, 2 и 4 — режимы просмотра, полного вывода (этап 5) они не дают.

## Тестовый репозиторий

Файл вида (`#` — комментарий):

```
A: B C
B: D
C: D
D:
```

Примеры: `tests/data/*.txt` (ромб, цикл, самозависимость, цепочка).
Зависимость от неописанного пакета — ошибка репозитория.

## Как это устроено

- Репозиторий NuGet: `{repo}/{id}/{версия}/{id}.nuspec`, id и версия в нижнем
  регистре, версия нормализуется. Группа зависимостей выбирается по
  `framework`: точное совпадение, затем группа без платформы, затем последняя.
- Диапазон версий заменяется нижней границей (NuGet берёт наименьшую
  подходящую версию); если границы нет — наименьшая версия из `index.json`.
- Вершина графа — пара (имя, версия). Вершины на глубине `max_depth`
  включаются в граф, но не раскрываются.
- Порядок загрузки — постпорядок итеративного DFS; рёбра в вершины, обход
  которых не завершён (циклы), пропускаются.

## Примеры (тестовый режим)

```
$ cat config.json   # package_name A, repository tests/data/cycle.txt, max_depth 5
$ make run CONFIG=config.json
Граф зависимостей (глубина <= 5), вершин: 4
  A -> B
  B -> C
  C -> A, D
  D -> (нет)
Цикл: A -> B -> C -> A
```

Три примера визуализации лежат в `examples/`: `diamond`, `cycle`, `demo_app`
(`.mmd` и `.svg`).

Порядок загрузки для `tests/data/diamond.txt`: `G D E B F C A`.

## Сравнение с реальным менеджером пакетов

Не выполнено: при разработке не было доступа к сети и к `dotnet`. Порядок
проверки и ожидаемые расхождения:

1. Создать проект, добавить пакет: `dotnet new classlib`,
   `dotnet add package <id> --version <версия>`.
2. Дерево: `dotnet list package --include-transitive`,
   `dotnet nuget why <проект> <пакет>`. Порядок загрузки: `dotnet restore -v d`.
3. Ожидаемые расхождения:
   - NuGet выбирает единственную версию пакета (nearest wins), а здесь одна
     вершина на пару (имя, версия), поэтому версии могут дублироваться;
   - `dotnet restore` загружает пакеты параллельно, порядок не детерминирован;
   - реальный выбор группы идёт по совместимости платформ, здесь — по
     совпадению `framework`;
   - исключаются пакеты, входящие в целевую платформу, диапазоны с
     исключающей нижней границей `(1.0,)` трактуются как включающие.

## Mermaid и SVG

Текст Mermaid сохраняется в `.mmd` и открывается в mermaid.live или
`mmdc -i graph.mmd -o graph.svg`. SVG `output_file` рисуется встроенным
модулем `svg.py` по тому же графу, а не через `mmdc`.

## Оформление

Проверяется правилами из сборника: строки <= 80 символов, функции <= 40
строк, не более 7 аргументов, docstring у всех функций, сложность <= 10,
без магических чисел в сравнениях, коммиты в формате Conventional Commits.
